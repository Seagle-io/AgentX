(01)Die IdeeDie Ideecontext packcontext pack
Multi-Agent-Systeme scheitern nicht an dummen Agents, sondern an verwässertem Kontext.

Ein Agent, den man auf ein Repository loslässt, liest vierzig Dateien, behält das falsche Drittel davon und arbeitet mit einem verschwommenen Verständnis. Bei AgentX trägt nur ein einziger Agent die Kosten der Erkundung: Der Projektleiter liest breit und schreibt dann für jede Aufgabe ein dichtes Pack von rund 1.000 Tokens, das bereits alles enthält. Der Ausführende liest nur das.

(02)Die RollenDie Rollen5 + 15 + 1

Fünf Berufe, ein Chef.

Der Projektleiter führt das Gespräch, schreibt das Briefing, zerlegt die Arbeit in Aufgaben, verfasst die Packs und startet die Agents in parallelen Wellen. Es gibt nie zwei davon.

01

Kundschafter

Findet, was gesucht wird, nur lesend. Der Einzige, der breit erkunden darf; er berichtet in höchstens 150 Zeilen.

02

Architekt

Entscheidet und liefert einen ausführbaren Vertrag. Schreibt keinen Produktionscode.

03

Implementierer

Programmiert in einem abgeschlossenen Rahmen: höchstens zwölf Dateien, der kleinstmögliche Diff.

04

Prüfer

Versucht, das Ergebnis zu zerlegen. Ohne Bearbeitungswerkzeug: Er stellt fest, er repariert nicht.

05

Chronist

Hält Wissen fest und verdichtet es. Bündelt die Rückmeldungen und verbessert die Pack-Vorlagen.

AgentX — Salle des agents
⌘R

Ein Arbeitsplatz pro Rolle, Übergaben dazwischen

Ein Arbeitsplatz leuchtet auf, sobald sein Agent arbeitet, und das Radar springt auf Rot, wenn eine Aufgabe blockiert ist. Die Agents sprechen nie miteinander: Sie reichen den Vault weiter, und jede Übergabe zeigt, was gerade weitergegeben wird.

(04)Die RegelnDie Regeln66

Was das Ganze zusammenhält.

Schutzmechanismen verweigern den Agents git push, Migrationen und destruktive Befehle: Die führt der Mensch selbst aus.

  1. 01

    Ein Pack ist die einzige Quelle der Wahrheit für seinen Ausführenden.

  2. 02

    Verträge werden abgeschrieben, nicht verlinkt.

  3. 03

    Eine Welle ist eine einzige Nachricht und N Agents parallel.

  4. 04

    „Nicht geprüft“ heißt „nicht erledigt“: Kein Test gilt als bestanden ohne seine tatsächliche Ausgabe.

  5. 05

    Ein blockierter Agent wird nie mit demselben Pack neu gestartet.

  6. 06

    Jedes Ergebnis hält fest, was in seinem Pack fehlte: So werden die Vorlagen besser.
